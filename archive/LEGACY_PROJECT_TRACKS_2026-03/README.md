# Canonical rule

`_projects/` is retired as a status surface.

A historical project file may explain **what happened**.

It may not establish **what is true now** without current verification.

For present state use:

1. Founder direction
2. `OPERATING_STATE.md`
3. canonical domain knowledge and current project/campaign evidence
4. historical `_projects` files only as provenance

---

# Why the files are not copied here

Git already preserves their exact contents, and the preservation branch `archive/pre-reconciliation-2026-09-29` captures the pre-reconciliation tree.

Duplicating four large project files into another archive directory would recreate the repository clutter this reconciliation is intended to remove.

# Durable lessons retained

Across the four tracks, several durable practices remain useful:

- preserve migration and technical receipts;
- distinguish resolved incidents from current blockers;
- protect conversion-critical infrastructure during platform changes;
- assess legacy assets before destroying them;
- record major product-path decisions;
- separate historical evidence from present operating state.

These lessons belong in the institution. The old status layer does not.
