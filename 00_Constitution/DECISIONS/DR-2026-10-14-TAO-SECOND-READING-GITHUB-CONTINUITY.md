## Options considered

1. Continue a local-only package and preserve it later: rejected by Founder’s continuity requirement and existing persistence doctrine.
2. Create a separate editorial system or new repository: explicitly prohibited.
3. Preserve the pilot in the existing campaign, subordinate it to current standards, record approval boundaries, and push a reviewed branch: selected by Founder.

## Decision

1. Existing GitHub repository `learn2tape19/finding-my-wei` is mandatory canonical authority for editorial standards, workflows, approved originals, decisions and production evidence.
2. Second Reading records belong in Campaign 001 `SECOND_READING_PILOT_2026/`; that directory is a campaign package, not an operating system. Existing canonical articles retain their authoritative locations and URLs.
3. Preserve Issues 001–016, their existing URLs and approved asset bytes. Missing historical evidence remains missing; do not create a historical Issue 009 URL or rewrite original outcomes.
4. Preserve WordPress → Buffer → Brevo → GA4 responsibilities. GitHub precedes execution and receives verification evidence afterward. Buffer and Brevo use approved WordPress-hosted media; GA4 measures outcomes, not publishing authority.
5. Reuse existing editorial/scientific review, distinct editorial reviewer, Founder direction/copy/visual/release gates, Phase 7A and existing publishing control plane. Pilot checklists cannot replace them.
6. Record approved decisions, source and change SHAs, asset manifests/hashes, platform IDs, exact-version approval and production verification in GitHub. State unperformed checks and unknown results explicitly.
7. Push the existing review branch only after bounded secret and change-scope review. Do not merge, publish, schedule or send without separate explicit Founder approval. A branch push is preservation, not approval of its drafts.

## Reasoning

The repository already contains the production architecture and the learning from earlier Tao issues. Reusing it preserves provenance and prevents local drafts, AI memory or a ZIP from becoming competing authority.

## Consequences

The local pilot checklist becomes a cross-reference to existing standards. The proposed reduced cadence, new copy, email/social-only reflection placement, artwork, audience and release remain unapproved. The current five-day completeness checker is not yet configured for the proposed reduced pilot. An approved production manifest and a narrowly scoped compatible checker change, if required, must precede any production-complete claim. No gate is waived here.

## Review trigger

Revisit if the Founder explicitly changes canonical repository or platform architecture, if standards conflict, or if implementation exposes a gap requiring a bounded, approved amendment. Resolve conflicts before execution; do not silently build substitutes.

## Supersedes / superseded by

Supersedes any interpretation that the local review package, exported copy or pilot checklist is independent editorial authority. Reaffirms the October 12 Work/preservation decision and existing governance. Does not supersede historical issue approvals or authorize relaunch content, assets, cadence, audiences, scheduling, sending, publishing or merging. No superseding record at creation.
