### Brevo API sender contract note

The Brevo API rejects `sender.email` and `sender.id` in the same request: *"Passing both `email` and `id` will result in an error."* The campaign was therefore submitted as `{"name": "Drew Freedman | Tao of Clinical Touch", "id": 3}` — **sender ID only, with the explicit name override**. Independent retrieval confirms this resolved to exactly the authorized sender: email `drew@mail.taoclinicaltouch.com`, id 3, explicit name (never `[DEFAULT_FROM_NAME]`). The deviation was in submission form only, forced by the API contract; no authorized value differs from the specification.

### Brevo capability note (carried forward)

`create_email_campaign` accepts `scheduledAt` and creates directly in `queued` state. **`update_email_campaign` and `send_email_campaign` remain unexposed** — a created campaign cannot be edited or rescheduled through this surface. Founder dashboard action is the only correction path. This is the unresolved gap first recorded in `ISSUE_007/WEDNESDAY/EXECUTION_LESSON_BREVO_SCHEDULING.md`.
