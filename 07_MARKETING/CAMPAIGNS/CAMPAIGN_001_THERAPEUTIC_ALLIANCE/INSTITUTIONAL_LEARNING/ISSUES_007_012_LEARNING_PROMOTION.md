# Issues 007-012 Institutional Learning Promotion

**Campaign:** Campaign 001 — Therapeutic Alliance  
**Mission Expression:** The Tao of Clinical Touch  
**Date:** September 11, 2026  
**Status:** Institutional learning review completed; durable production lessons promoted

---

## Purpose

This record closes an inheritance gap that developed across recent Tao issues.

Issues 007-011 increasingly accumulated strong issue-level controls, approved asset folders, execution handoffs, manifests, copy locks, preflight records, checksums, and execution receipts. However, durable production lessons were not consistently promoted back into a shared standard before the next issue began.

The result was local improvement without reliable institutional inheritance.

Issue 012 exposed the cost of that gap and triggered this review.

## What Was Already Institutionalized

The repository already contained strong institutional principles:

1. The blog/article is the canonical publication and other channels are adaptations.
2. Editorial work precedes creative production.
3. Platform content must trace to canonical editorial material rather than be independently invented.
4. Founder approval is authoritative.
5. Publication work requires QA, deployment controls, analytics, and archival discipline.
6. Institutional learning should update standards when lessons are durable and applicable to future work.

These principles were not the primary failure.

The failure was **inheritance and promotion**: issue-level production knowledge was becoming more sophisticated than the shared visual-production standard available to the next issue.

---

## What Issues 007-011 Demonstrated

### Issue 007

Issue 007 established increasingly explicit Founder approval gates, approved-asset handling, asset-import instructions, and execution handoffs. It also explicitly instructed execution to inherit current Finding My Wei governance and Foundry execution standards.

**Durable lesson:** execution packets should reference institutional authority rather than attempt to become a parallel authority.

### Issue 008

Issue 008 expanded the operational controls around approved assets, execution holds, Founder directives, production status, and execution receipts.

**Durable lesson:** production state and execution state must be explicit. Approval does not automatically equal permission to deploy.

### Issue 009

Issue 009 made copy locking, asset verification, manifests, checksums, preflight, and execution hold/release more explicit.

**Durable lesson:** canonical copy, binary assets, and deployment readiness are separate things and each requires verification.

### Issues 010-011

Issues 010 and 011 converged toward a more mature weekly packet: canonical article, master copy, email copy, publishing schedule, approved assets, manifest, checksums, execution handoff, and execution receipt.

**Durable lesson:** the weekly issue can be compact and repeatable when canonical source, approved assets, deployment schedule, and execution evidence have clearly separated roles.

However, the production packet still carried too much knowledge locally. The next issue did not automatically inherit all of the visual-production lessons that produced the prior issue.

---

## Issue 012: Root Cause

Issue 012 visual production encountered preventable rework involving:

- copy drift after editorial approval;
- incorrect dimensions;
- incorrect aspect ratio;
- anatomical and limb-orientation errors;
- visual stages that risked moving ahead of the approved editorial movement;
- Story sequence continuity;
- confusion between earlier architecture and a later Founder-approved production variation;
- temporary loss of provenance for an already approved Wednesday Story 1 asset.

The root problem was not simply imperfect image generation.

The root problem was that accumulated lessons had not been converted into a mandatory **pre-generation visual production gate system** inherited by the next issue.

---

## Institutional Promotion

The durable learning from Issues 007-012 has now been promoted to:

`07_MARKETING/STANDARDS/VISUAL_PRODUCTION_AND_APPROVAL_STANDARD.md`

That standard establishes:

- source authority hierarchy;
- locked-copy gate;
- visual-stage gate;
- anatomy/clinical-logic gate;
- format/aspect gate;
- current Tao build order: Feed -> Landscape -> Story 1 -> Story 2 -> Story 3;
- exact-dimension verification after approval;
- Founder approval and provenance protection;
- canonical naming and 25-asset weekly completeness;
- repository-first handoff architecture;
- explicit known failure classes to prevent before generation.

---

## Scope Decision

Not every Issue 012 preference was promoted.

Issue-specific visual choices, such as whether a particular week uses a ripple, a particular room, a particular subject, or a specific compositional device, remain issue-level decisions unless separately promoted through brand governance.

The promoted rules are those that should remain true even when the weekly theme, imagery, or campaign changes.

---

## New Inheritance Rule

Beginning with Issue 012 closeout and Issue 013 planning:

1. Read current institutional publishing/editorial standards.
2. Read `VISUAL_PRODUCTION_AND_APPROVAL_STANDARD.md` before visual production begins.
3. Read the campaign's current authority/arc records.
4. Create and lock issue-specific editorial architecture and copy.
5. Produce visuals through the inherited gates.
6. Close the issue with a learning review.
7. Promote only durable new lessons to the appropriate institutional standard.

The next issue should not require the Founder to reteach a lesson already learned.

## Closeout Statement

The campaign is now returning to the Finding My Wei learning loop:

**Work -> Observe -> Learn -> Document -> Promote -> Inherit -> Work Better**

Issue 012 will be the first current issue handed off after this corrective promotion.
